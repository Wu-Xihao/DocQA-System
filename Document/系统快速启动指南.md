# DocQA 系统快速启动

推荐先跑通演示，再接入自己的文档和模型。以下均在 **PowerShell** 执行。

## 1. 准备环境

```powershell
conda activate docqa
Set-Location 'E:\Documents\ChatGPTWorkSpace\DocQA System'
python -m pip install -r requirements-web.txt
```

已有 Python 3.12 环境即可，无须重建；使用内置 Agent，无须安装外部 CodeAgent 或 Node.js。

## 2. 先启动演示（不需要模型服务）

首次执行前两条生成样例和索引；已有可用的演示索引时直接启动：

```powershell
python scripts/generate_docbase_samples.py --output runtime/quickstart-samples
python scripts/docqa.py docbase build runtime/quickstart-samples/sources.json --output runtime/docbase --config configs/docbase.demo.yaml
python scripts/docqa.py web run --config configs/web.demo.yaml
```

浏览器打开 **http://127.0.0.1:8765**，提问：`SD5993 的 FE_HEART_Start 如何启动心跳？`

看到回答后点击引用，检查原文与下载。演示使用合成模型，只验证运行流程；停止按 **Ctrl+C**。本节不需要启动 Service。

## 3. 使用自己的文档（需要真实模型服务）

### 3.1 配置：复制模板，保存为本机文件

已有同名本机文件时直接编辑，不覆盖。所有 `local.*.yaml` 均已被 Git 忽略。

| 模板 → 本机文件（均在 configs 中） | 必须配置 |
| --- | --- |
| [docbase.example.yaml](../configs/docbase.example.yaml) → `local.docbase.yaml` | dense、sparse、reranker 的完整 endpoint、model、revision、tokenizer_revision；dense.dimension、sparse.vocab_size 填真实值 |
| [service.example.yaml](../configs/service.example.yaml) → `local.service.yaml` | `allowed_source_roots: ['E:/DocQAData']`；将上一个文件的**全部内容**嵌入 `retrieval:` 下 |
| [web.example.yaml](../configs/web.example.yaml) → `local.web.yaml` | 填 `agent.generator`、`agent.verifier` 的 endpoint/model/revision；同一份 DocBase 配置嵌入 `agent.retrieval:` 下 |

嵌入是复制 YAML 内容并正确缩进，**不能填写配置文件路径**。三处 DocBase 配置应保持一致。Web 的路径保留：

```yaml
index: ../runtime/service-user/index
state: ../runtime/web-real
service_state: ../runtime/service-user
```

真实模式保留 `mode: http`。endpoint 必须是完整接口地址；检索服务须兼容项目 [HTTP 协议](./DocBase模块设计实现与测试指南.md#71-docbasehttpv1)，仅有模型名称无法运行。generator/verifier 可使用同一 Chat 服务，仍需分别配置。

按配置中的 `api_key_env` 设置密钥，例如：

```powershell
$env:DOCQA_CHAT_KEY = '替换为你的实际密钥'
```

其余默认变量：`DOCQA_VERIFIER_KEY`、`DOCQA_EMBEDDING_KEY`、`DOCQA_SPARSE_KEY`、`DOCQA_RERANKER_KEY`；图片模型另用 `DOCQA_VISION_KEY`。**每个启动终端分别设置所需变量**；服务不需要认证时将对应 `api_key_env` 设为 `null`。

### 3.2 导入资料并启动后台

先创建 `E:\DocQAData` 并放入自己的 PDF/DOCX/PPTX。建议先用纯文字文档；带图/扫描件需在 Service 的 `parse` 中配置 VL/OCR，模板见 [doc2md 配置](../configs/doc2md.example.yaml)。缺少解析能力时可能待复核，不能当作完整入库。

**终端 A**：完成第 1 节环境切换及密钥设置后，首次注册目录，再持续运行：

```powershell
python scripts/docqa.py service source add 'E:\DocQAData' --types pdf,docx,pptx --recursive --state runtime/service-user --config configs/local.service.yaml
python scripts/docqa.py service run --state runtime/service-user --config configs/local.service.yaml
```

**终端 B**：同样切换环境、目录并设置密钥。先确认索引已生成且 documents 大于 0，再启动网页：

```powershell
python scripts/docqa.py service index status --state runtime/service-user --config configs/local.service.yaml
python scripts/docqa.py web run --config configs/local.web.yaml
```

打开 **http://127.0.0.1:8765**，刷新后选择文档并提问。日常再次启动只需运行两个终端的 `service run` 和 `web run`；停止分别按 **Ctrl+C**。修改配置后重启。

| 遇到的问题 | 优先检查 |
| --- | --- |
| 网页依赖未就绪 / 没有文档 | 索引是否已发布、路径是否正确；`service job list --job-state failed` 配合同一 `--state` / `--config` 查失败任务 |
| MODEL_NOT_CONFIGURED / 模型请求失败 | 配置必填项、当前终端密钥及模型接口协议/连通性 |
| PROFILE_MISMATCH | Service 与 Web 的 DocBase 配置保持一致；修改索引配置后等待后台重新构建再刷新 |
| 8765 端口被占用 | 修改所用 Web 配置的 port，重启后访问新端口 |
