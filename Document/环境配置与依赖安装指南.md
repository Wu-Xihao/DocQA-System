# DocQA 环境配置与依赖安装指南

> 适用环境：Windows x86-64、Conda 独立环境、Python 3.12.x。  
> 编制日期：2026-10-24。  
> 依据：[系统详细架构设计](./DocQA系统详细架构设计与实施方案.md)第 3、7、8、18 章。

## 1. 当前步骤与交付范围

Python 环境已由用户安装。下一步先完成核心库和开发工具安装，再检查系统级工具与模型服务能力。

本次提供的是**初始依赖范围清单**，尚未在用户新建的 Conda 环境中安装/解析，不是经过联调验证的锁文件。安装器选择满足约束和 Python 版本的依赖；安装、导入、`pip check` 和后续样本验证都通过后，再保存准确版本。

已提供文件：

| 文件 | 内容 | 当前是否安装 |
| --- | --- | --- |
| `requirements.txt` | 核心运行依赖 | 必装 |
| `requirements-dev.txt` | 自动包含核心依赖，再加测试/代码检查工具 | 当前开发建议直接安装此文件 |
| `requirements-web.txt` | 自动包含核心依赖，再加 FastAPI/Uvicorn | 实现 Web 时安装 |
| `requirements-service.txt` | 自动包含核心依赖，再加 watchdog | 实现目录监控时安装 |
| `scripts/check_environment.py` | 版本范围、导入、Python 位数及 SQLite 检查 | 安装后执行 |

这些范围是工程起步选择，不代表范围内每一种组合均已验证。`portalocker` 只提供锁能力，不能替代架构中的任务租约、fencing/CAS 和索引发布协议。

SQLite、pathlib、json、hashlib、logging、subprocess、asyncio 等来自 Python 标准库，无需单独通过 pip 安装。BM25 首版按设计自行实现，BGE-M3 learned sparse 另由服务或本机 provider 提供。

## 4. 手动安装命令

在 Anaconda Prompt 中执行：

```bat
conda activate docqa
cd /d "E:\Documents\ChatGPTWorkSpace\DocQA System"
python --version
python -m pip --version
python -m pip install --upgrade pip
python -m pip install --prefer-binary -r requirements-dev.txt
```

若环境名称不同，用实际名称替换 `docqa`。`--prefer-binary` 优先使用可用二进制包，不会禁止 jieba 等仅有源码分发的包安装。使用 `python -m pip` 确保 pip 对应当前解释器。

如使用 PowerShell，切换项目目录改为：

```powershell
Set-Location -LiteralPath 'E:\Documents\ChatGPTWorkSpace\DocQA System'
```

后续选做：

```bat
python -m pip install --prefer-binary -r requirements-web.txt
python -m pip install --prefer-binary -r requirements-service.txt
```

若安装报错，保留第一处实际失败的包名、完整报错、Python/pip 版本和当前解释器路径；不要靠随意降低全部包版本消除提示。`No matching distribution`、网络/证书问题和版本冲突是不同原因，按错误分别处理。

## 5. 系统级工具：需要独立安装

### 5.1 Tesseract OCR

目标：Tesseract 5.x、64 位，安装 `eng` 和 `chi_sim` 语言数据；需要处理繁体时再加 `chi_tra`。入口：[Tesseract 官方安装说明](https://tesseract-ocr.github.io/tessdoc/Installation.html)。Windows 二进制安装包通常由官方文档所列第三方构建渠道提供，按该说明选择。

将实际安装目录加入 PATH，重新打开终端后执行：

```bat
tesseract --version
tesseract --list-langs
```

检查语言列表至少包含 `eng`、`chi_sim`。只安装 Python 库不代表 OCR 引擎或语言包已就绪。本设计直接封装 Tesseract 进程，当前不依赖 `pytesseract` 包。

### 5.2 LibreOffice

目标：官网当前稳定发行的 Windows x86-64 版本，用于 DOC/PPT 转换以及 DOCX/PPTX 的固定页面渲染。入口：[LibreOffice 官方下载](https://www.libreoffice.org/download/)。

安装后记录具体版本与字体环境。常见检查方式（若安装路径不同，修改路径）：

```bat
"C:\Program Files\LibreOffice\program\soffice.com" --version
```

PowerShell 对带引号可执行文件使用：

```powershell
& 'C:\Program Files\LibreOffice\program\soffice.com' --version
```

若使用脚本的 `--system` 检查，将 `LibreOffice\program` 目录加入 PATH；后续系统实现也可支持配置明确可执行路径。

缺少这些工具时可以继续契约、配置和模型 Mock 开发，但不能判定扫描件 OCR、Office 完整视觉渲染验收通过。外部工具可启动，也不等于已经验证宏/外链隔离与复杂文档转换质量。

## 6. 本机模型依赖的安装边界

当前方案优先通过 HTTP 接入内部 Chat、VL、Embedding、Reranker、Sparse 服务，调用侧使用 httpx。

如果 BGE-M3 服务真实返回稀疏权重，本机不需要为此安装 PyTorch/CUDA。若决定本机运行 BGE-M3，再单独确认 NVIDIA GPU/驱动、CPU/GPU 推理、内存、PyTorch 与 FlagEmbedding 版本，并形成独立依赖组。当前不提供未经硬件核验的 CUDA 安装命令。

普通 dense embedding 响应不等于 learned sparse 能力，需按架构的模型能力矩阵探测。模型实际 ID、协议、维度、输入限制、认证与版本仍待联调，不能因 Python 依赖安装完成就标为接入成功。

## 7. 安装后检查

```bat
python -m pip check
python scripts\check_environment.py --dev
```

安装系统工具并配置 PATH 后再执行：

```bat
python scripts\check_environment.py --dev --system
```

如安装了全部可选组：

```bat
python scripts\check_environment.py --dev --web --service --system
```

脚本检查当前 Python/位数、所选依赖范围、模块导入、内存 SQLite 查询；`--system` 只检查 PATH 能否找到外部程序，不验证语言包、转换质量、锁协议或模型连接。

`pip check` 检查已安装包声明的依赖关系；导入检查可进一步发现部分原生 DLL/模块问题。两项均通过后，才把“Python 依赖安装检查”标为通过；系统功能还需要真实样本和模型服务验证。

## 8. 保存安装结果与下一步

安装检查通过后，在 Anaconda Prompt 中保存环境快照：

```bat
python -m pip freeze > requirements-installed.txt
conda env export --from-history > environment-history.yml
```

`requirements-installed.txt` 是当前环境全部已安装分发的版本快照，可能包含 Conda 预置包或本地路径；`environment-history.yml` 是 Conda 显式安装历史，通常不包含通过 pip 安装的完整依赖。两者均不是带哈希、跨平台验证的交付锁文件。后续 S0-07 在样本联调后使用选定锁工具形成真正的可复现锁定清单。
